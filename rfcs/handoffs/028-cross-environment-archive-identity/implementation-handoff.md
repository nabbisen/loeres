# Developer Handoff — RFC 028 cross-environment archive identity anchor

**Governing RFC.** `rfcs/accepted/028-cross-environment-archive-identity.md` (design frozen 2026-09-15).
**Assigned to.** Implementer tier.
**Ordering.** After architect review 052's follow-ups F1–F3; **before** RFC 027 slice S2. Must land before the next release gate runs, because RFC 028's fourth exit criterion is observed there.

---

## 1. Purpose

Record the digest that is actually reproducible across environments, and say
plainly what each digest identifies, so that a correct local rebuild is never
mistaken for tampering.

## 2. Background

`0.21.0`'s release gate produced archive SHA-256 `6b056905…b72a` in CI and
`d52329ca…5664` locally, for the same revision `e930db2`. The tracked content
manifest and the **uncompressed tar stream** (`0748304f…457b`) were byte-identical;
only gzip output differed. Evidence records only the compressed digest.

As built today (`xtask/src/checks/release_gate/package.rs`):

- the archive comes from `git archive --format=tar.gz --output=<archive>`;
- its digest comes from `fn sha256(root, archive)`, which shells out to `sha256sum`
  and validates a 64-hex result;
- the gate extracts with `tar --gzip`, so `gzip` is already a runtime requirement;
- `EVIDENCE.md` is rendered from a `format!` over `ToolVersions`, and tests live in
  `package.rs`'s `mod tests`.

## 3. Change scope

### 3.1 Compute the uncompressed digest from the archive the gate produced

Add `fn uncompressed_tar_sha256(root: &Path, archive: &Path) -> Result<String, String>`:

- spawn `gzip -dc <archive>` with stdout piped straight into a `sha256sum` child's
  stdin — two `Command`s, **no shell string, no `sh -c`**;
- require both children to exit successfully; a `gzip` failure (not gzip data,
  missing tool) is an `Err`, never an empty or partial digest;
- validate the result exactly as `sha256()` does (64 lowercase hex).

Call it immediately after `let digest = sha256(&source, &archive)?;`, before clean
extraction, so the anchor is bound to the exact bytes that ship.

### 3.2 Evidence text

In `EVIDENCE.md`, directly after the `**Archive SHA-256:**` line, add:

```text
**Uncompressed tar SHA-256:** `<hex>`
```

and, as its own short paragraph immediately below the header block, exactly:

```text
The uncompressed tar SHA-256 is the cross-environment identity of this source
artifact's content and layout. The archive SHA-256 identifies this build's bytes
and is not expected to reproduce in another environment (RFC 028).
```

### 3.3 Tool versions

`ToolVersions` gains `gzip`: the first line of `gzip --version`, rendered in the
tool list after `tar`. Update the test fixture (`tar test`-style placeholder).

### 3.4 Documentation

- `docs/src/verification.md`, in the release-gate paragraph: to verify a download or
  a rebuild, run `gzip -dc loeres-vX.Y.Z.tar.gz | sha256sum` and compare with
  **Uncompressed tar SHA-256**; the **Archive SHA-256** only confirms that a
  downloaded file is the exact file CI produced.
- `docs/src/development.md`, where `release-gate`'s evidence is described: one
  sentence naming both digests and what each identifies.

## 4. Explicit non-change scope

- **No workspace dependency** — no `flate2`, no `sha2`. Shell out, per the existing
  `sha256sum` convention.
- Do not change how the archive is built: no pinned gzip level, no format change.
- Do not remove or rename **Archive SHA-256**.
- Nothing under `crates/` or `.github/workflows/` — CI already has `gzip`.
- Do not edit RFC 019 (shipped; RFC 028 is additive), the `0.21.0` tag, or any
  historical evidence bundle.

## 5. Required tests

1. **Two compression levels, one identity.** Build a deterministic tar stream large
   enough to compress differently (≥ 64 KiB; for example `git archive --format=tar`
   of a fixed commit, or generated bytes), compress it with `gzip -1 -n` and
   `gzip -9 -n`, then assert the two archive digests **differ** — a stated
   precondition, so the test cannot pass vacuously — and that
   `uncompressed_tar_sha256` returns **equal** values for both.
2. **Fail closed on non-gzip input.** A plain file yields `Err`, not a digest.
3. **Rendering.** The evidence text contains `**Archive SHA-256:**` followed by
   `**Uncompressed tar SHA-256:**`, in that order, plus the identity paragraph
   verbatim.

## 6. Required evidence

- fmt, clippy `-D warnings`, tests, MSRV 1.85, `cargo xtask check`, `mdbook build
  docs --dest-dir target/xtask-book/local`.
- `cargo xtask release-gate --intended-tag 0.21.1` on a **clean committed** revision
  (move any existing `…-v0.21.1` evidence directory aside first). Show both digest
  lines from the produced `EVIDENCE.md`, **and** recompute by hand:
  `gzip -dc <archive> | sha256sum` must equal the recorded uncompressed digest.
- RFC 028 exit criterion 4 — CI and local uncompressed digests observed equal — is
  **not** claimable here; it belongs to the next real release.

## 7. Prohibited shortcuts

- Computing the uncompressed digest from a *second* `git archive --format=tar` run.
  That identifies a tree, not the shipped file, and would let the anchor and the
  artifact drift apart.
- Interpolating paths into a shell command.
- Reporting the unit tests as end-to-end evidence.
- `#[allow(dead_code)]` — remove, never suppress.

## 8. Known risks

| Risk | Mitigation |
|---|---|
| `gzip -1` and `-9` produce identical bytes for a small input | Test precondition asserts the archive digests differ; size the input up until they do |
| `gzip` missing in some environment | Already required by extraction; fail closed with a named-tool error like the other probes |
